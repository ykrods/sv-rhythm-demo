# Health Check
プロジェクトの健全性をチェック項目（C1 ~ C7）ごとに確認し、指摘をユーザに報告する。
呼び出し元ごとに実行する項目と scope は `AGENTS.md` の「Health Check」を参照する。

引数: `$ARGUMENTS`

## 引数
- 形式: `[チェック項目] [scope]`（順不同）
  - チェック項目: `C1,C3` のようにカンマ区切りで指定する
  - scope: `task=<タスクディレクトリ名>` または `project`
  - 例: `C1,C3 task=20261015-xxx`、`C6`
- 指定がない場合は全項目・`project` scope で実行する
- 解釈できない引数がある場合は、チェックを実行せずユーザに確認する

## scope とチェック対象
scope は `task`, `project` の2種類存在する。
- `task`: 指定したタスクに関係する範囲を対象とする
  - 変更ファイルは `git status`, `git diff` で特定する。未追跡のファイル（`git status` で `??` と表示されるもの）も含める。
- `project`: プロジェクト全体を対象とする。

### scope の影響範囲
- scope は C4-2, C6 のチェック対象に影響する
- C1 ~ C3, C4-1, C5 は npm scripts の結果で判定するため、scope に関わらずプロジェクト全体が対象になる
- C7 は scope に関わらず、[C7] の「対象」に記載された範囲を対象とする

## チェック項目

### [C1] ビルドが通る
- 照合元: `npm run build`
- 確認観点: 終了コード、出力された警告
- 指摘とする条件: 失敗した場合。警告が出た場合も報告する

### [C2] 型チェックが通る
- 照合元: `npm run check`
- 確認観点: svelte-check と tsc のエラー・警告
- 指摘とする条件: エラー・警告が 1 件以上ある場合

### [C3] テストが通る
- 照合元: `npm run test`
- 確認観点: 失敗したテスト
- 指摘とする条件: 失敗したテストがある場合

### [C4] コーディング規約に従っている
#### [C4-1] lint
- 照合元: `npm run lint`
- 確認観点: lint の結果
- 指摘とする条件: lint の違反がある場合

#### [C4-2] lint で表現できない規約
- 照合元: `docs/coding-guidelines.md`, `docs/architecture.md` の「設計方針」
- 確認観点: 照合元の規約（ロジックの分離など）を対象が守れているか
- 対象:
  - project scope: `src/`, `tests/`
  - task scope: `src/`, `tests/` 以下の変更ファイル
- 指摘とする条件: 規約に反するコードがある場合

### [C5] 依存パッケージの制約に従っている
- 照合元: `npm run check-deps`, `docs/architecture.md` の「依存パッケージ」
- 確認観点: 直接依存しているパッケージごとの推移的な依存数
- 指摘とする条件: 30 以上のパッケージがある場合

### [C6] 実装と仕様の整合性
- 照合元:
  - project scope: `docs/spec/`
  - task scope: 対象のタスクの requirements.md, plan.md（存在する場合）
- 対象:
  - project scope: `src/`, `tests/`
  - task scope: `src/`, `tests/` 以下の変更ファイル
- 確認観点: 仕様に書かれたことが実装されているか、実装が仕様と異なっていないか、仕様にない変更をしていないか
- 指摘とする条件: 未実装、仕様と異なる実装、仕様の範囲外の変更がある場合
- 補足:
  - task scope で実行する際、`src/`, `tests/` に含まれないファイル（`index.html` や `public/` 以下のファイル）は対象外
  - task scope で実行する際、requirements.md や plan.md と関連する spec が存在していても、その spec の内容との整合性については対象外

### [C7] ドキュメント間の整合性
- 照合元: `docs/`, `AGENTS.md`
- 対象: `docs/`
- 確認観点: ドキュメント間で、同じ事項について矛盾する記述が存在しないか
- 指摘とする条件: 明確な矛盾が存在する場合
- 判定ルールの詳細:
  - 各ドキュメントの目的と抽象度を尊重する
  - 記述されていない事項を、原則として不足とはみなさない
  - 抽象的な説明と具体的な説明は、両立可能であれば矛盾とみなさない
  - `docs/proposal.md` は初期計画として扱い、他のドキュメントとの矛盾を指摘しない
  - `docs/decisions/` の ADR は記録時点の判断として扱い、他のドキュメントとの食い違いを指摘しない（`docs/index.md`「ADR について」）
  - 実装コードとの整合性は C4・C6 で確認するため、C7 では扱わない

## 実行ルール
- チェック中にソース・ドキュメントの修正は行わない（修正はユーザの指示を受けてから行う）
- 判断できない点は推測で問題なしとせず「不明」として報告する
- 指摘に重要度は付けない。指摘はすべてユーザに報告し、対応はユーザが決める

## 実行手順
1. 引数を解釈し、実行するチェック項目と scope を決める
2. 「scope とチェック対象」セクションに従い、対象ファイルを特定する
3. C1 ~ C5 を実行する
   - npm scripts で判定する C1 ~ C3, C4-1, C5 をすべて実行する場合は `npm run verify` を実行する（途中で失敗しても全項目が実行される）
   - 一部だけの場合は、該当する npm scripts（`build` / `check` / `test` / `lint` / `check-deps`）を個別に実行する
   - C4-2 は、対象のファイルを読んで自分で確認する
4. C6・C7 は general-purpose のサブエージェントに依頼する
   - 理由: 実装した agent 自身の判断や会話の内容に引きずられず、docs とコードだけを根拠に確認するため
   - 依頼のプロンプトに含める内容
     - このファイル（`.claude/skills/health-check/SKILL.md`）のパスと、その定義に従ってチェックすること
     - 実行するチェック項目（C6・C7 のうち指定されたもの）と scope
     - `task` scope の場合はタスクディレクトリと変更ファイルの一覧
     - ファイルの修正を行わないこと
     - 指摘を「報告形式」の形式で返すこと
5. C1 ~ C5 の結果とサブエージェントの指摘をあわせて報告する
   - サブエージェントの指摘は取捨選択せず、そのまま報告する

## 報告形式
- 指摘は `[ID] 場所 — 内容 — 根拠` の形式で 1 件ずつ書く
  - 場所は `ファイルパス:行番号` の形式とする（ファイル全体・複数箇所に関わる場合はファイルパスのみでよい）
  - 根拠には参照したドキュメントの箇所を示す（例: `docs/spec/layout.md「論理座標」`）
  - 判断できない点は内容の先頭に `不明:` を付ける

- 最後に、チェック項目ごとの結果を一覧で示す。実行しなかった項目は「未実行」とする
  - id に C4-1, C4-2 のように枝番号がついている場合、一覧レポート時は C4 としてまとめる

```
[C4-2] src/scenes/Play.svelte:20 — 判定の計算をコンポーネント内で行っている — docs/architecture.md「ゲームロジックの分離」
[C6] src/scenes/Play.svelte:5 — viewBox が 0 0 360 600 になっている — docs/spec/layout.md「論理座標」
[C7] docs/spec/layout.md:10 — 論理座標のサイズを 360×600 としており、用語集の viewBox `0 0 360 640` と矛盾している — docs/glossary.md「論理座標」
[C7] docs/architecture.md — 不明: 「Scene」節の Scene の切り替えと docs/spec/scene-transition.md「遷移の流れ」が、同じ事項について異なる手順を述べているのか判断できない — docs/spec/scene-transition.md「遷移の流れ」

| ID | 結果 |
|---|---|
| C1 | OK |
| C2 | OK |
| C3 | OK |
| C4 | 指摘 1 件 |
| C5 | OK |
| C6 | 指摘 1 件 |
| C7 | 指摘 1 件 / 不明 1 件 |
```
