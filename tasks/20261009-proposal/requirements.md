## 決定事項
- 本プロジェクトは習作である
- 収録曲は 1 曲のみ
  - 曲は後で自作する予定
- 画面は以下の 2 つ
  - 開始画面
  - ゲーム画面
- 目的: 
  - svelte で簡単なゲームであればシンプルなコードで作れることを示す
  - ブラウザゲームの基本的な手法について学ぶ(requestAnimationFrameでのフレーム制御と描画)
- スコープ / 対象外: 
  - やること: 開始画面からゲーム画面への遷移、ノーツの落下と判定、スコア表示、1曲分の再生、リザルト(ポップアップの想定)の表示
  - やらないこと: 曲の選択、譜面エディタ、ランキングやオンライン機能、難易度の切り替え、設定画面
- 技術的な制約
  - Svelte 5 で実装
  - SvelteKit は個人的嗜好で必須でない限り使わない
  - ブラウザで動くゲームであり、バックエンドは不要
  - ゲーム画面は svg で構成する。これは canvas での描画より svg (or DOM) の方が Svelte との相性が良いことによる。
  - 音声データについて、単純化のため譜面データと音声を同時に開始すれば良いように作成する（プログラム側での調整を不要にする）
    - (technical note): 音声側の audio.currentTime などに譜面の進行を合わせる形にすればズレは少なくなる
  - 画面サイズ
    - 縦画面を前提とし、ゲーム領域の縦横比は 9:16 で固定する
    - スマホではブラウザの表示領域いっぱい、PC（および横向きのスマホ）では縦長の領域を中央に配置する
      - 縦長すぎる端末では上下に余白が出ることを許容する
      - 検討: 幅固定・高さ可変（端末の縦横比に合わせて画面を使い切る）案もあったが、実装の単純さと端末間で見え方を揃えることを優先して 9:16 固定とした
    - ゲーム画面は SVG の論理座標（viewBox）で描画し、実際の画面サイズに依存しないようにする
    - Fullscreen API は使わない（iOS Safari が非対応のため）
    - タッチ操作時のスクロール・拡大・テキスト選択を抑止する
- ゲーム仕様(これはプロポーザル段階での仕様なので、将来的には spec 以下のドキュメントを正とする)
  - オーソドックスなノーツが上から降ってきて、バーに触れるタイミングでボタンを押すタイプのゲームを作る
  - レーン数: 5
  - スコア判定: Great/Good/Bad/Miss の4種類があり、ボタンを押したタイミングがどれだけ一致しているかにより判定が変わる
  - 入力はキーボードまたはタッチで行う。どちらか一方だけで操作が完結するように作る

    - 具体的には「開始」ボタン以下に SPC ボタンで開始 のような注意書きを書いて、タップ / キーボード どちらでも開始できるようにするなど
