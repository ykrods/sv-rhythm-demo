# requirements: test

## 目的
自動テストを実行できる環境を整備する。
今後実装するゲームロジック（ノーツの進行、判定、スコア計算など）をテストで確認できるようにする。

## タスク種別
実装（開発環境の設定）

## 前提
- `docs/proposal.md`
- `docs/architecture.md`

## やること
- Vitest の導入
  - 既存の `vite.config.ts` の設定を共有して動かす
- npm scripts の追加
  - `npm run test`: テストを 1 回実行して終了する（watch モードにしない）
- テストファイルも `npm run check` の型チェック対象に含める
- 環境が動作することを確認するための最小限のテストを 1 つ用意する
- テストの方針を `docs/architecture.md` に節を追加して記載する
  - テストの対象は `src/lib/` の純粋なロジックに対して行う
  - `docs/architecture.md` に設計方針の節を追加し、テストしやすくするため、ゲームロジックをコンポーネントから分離する旨を記載する。
    - 例) ロジックを時刻などを引数で受け取る純粋関数として切り出す。関数ごとにファイルを作成する。
- AGENTS.md の Commands に `npm run test` を追記する

## やらないこと
- ゲームロジックそのものの実装とそのテスト（後続タスクで行う）
- コンポーネントテスト（@testing-library/svelte + jsdom など）の導入
- E2E テストの導入
- カバレッジの計測
- ヘルスチェックへの組み込み（`20261015-health-check` で行う）
- CI への組み込み

## テストファイルの配置・命名規則
- `tests/` 以下にテストファイルをまとめる。パスをテスト対象と揃える
  - 例) `src/lib/time.ts` のテストファイルは `tests/lib/time.test.ts` に作成する
- 付属的に、現状 lint の対象が `src/` になっているので、 `tests/` を含める
