# play

ゲーム画面（Play Scene）の仕様。
現状は静的な表示要素（背景画像・レーン・判定バー）、曲の進行に合わせて流れる小節線とノーツ、曲の再生、入力（キーボード・入力ボタン）とノーツの判定のみで、スコア・コンボ・リザルトなどは未実装。

## 表示要素
座標は論理座標（`docs/spec/layout.md`「論理座標」）で示す。
重なり順は下から背景画像・レーン・入力ボタン・小節線・判定バー・ノーツ・判定の結果の順とする。
- 入力ボタンの押下中の表示は判定バーより下のレーン面の表現のため、レーンの直上に重ねる
- ノーツは、判定バーに重なる瞬間（叩くタイミング）に隠れないよう、判定バーの上に重ねる
- 判定の結果は、ノーツに隠れないよう最前面に重ねる

- 背景画像
  - Title と同じく `src/assets/bg.webp` を Scene 全面に表示する（`preserveAspectRatio="xMidYMid slice"`）
  - 画像の読み込みが終わるまでは、暗い紺色（`#0d0b2e`）の下地を表示する
- レーン
  - 5 本のレーンを、奥行きのある表現（手前が広く奥が狭い台形）で表示する（「レーンの形」を参照）
  - 背景は透過ありの濃紺（`#0a0a2e`、不透明度 0.6）で塗る
  - レーンの両端と間に境界線（計 6 本）を引く。色はネオン調の青（`#4fc3ff`）、線幅 1.5 で、発光させる
    - 線幅は奥でも一定とする
- 判定バー
  - 画面の下 2 割の位置（y = 512）に、画面幅いっぱい（x = 0〜360）の横線を表示する
  - 色はレーンと同じネオン調の青（`#4fc3ff`）。レーンの境界線より太く（線幅 3）、発光を強くする
- 小節線
  - 曲の小節の頭を示す横線を、レーン全体の幅で表示し、曲の進行に合わせて流す（「小節線」を参照）
  - 背景の要素として目立たないよう、ネオン調の青（`#4fc3ff`）を不透明度 0.4、線幅 1 で引き、発光させない
    - 線幅は奥でも一定とする
- ノーツ
  - 譜面のノーツを、指定されたレーン上に曲の進行に合わせて流す（「ノーツ」を参照）
  - ネオン調の桃色（`#ff5fd2`）で塗り、白（`#fff`）の縁取り（線幅 1）を付けて、発光させる
    - レーン・小節線・判定バーの青と区別でき、Title のロゴのグラデーション（水色→桃色）と色味を揃える
- 入力ボタン
  - 判定バーより下（y = 512〜640）のレーンの部分を、レーンごと（5 個）の入力ボタンとする（「入力」を参照）
  - 押下していないときは、ボタンとしての描画を行わない（レーン・境界線の表示のみ）
  - 押下中は、そのレーンの判定バーより下の部分（台形）を、ネオン調の青（`#4fc3ff`）の縦のグラデーション（判定バー側で不透明度 0.5、画面の下端で 0）で塗る
  - キーの割り当て（`A` / `S` / `D` / `F` / `G`）を、白字・不透明度 0.4、Orbitron の太字、サイズ 14 で表示する
    - y は判定バーと画面の下端の中間（y = 576）
    - x は両端の文字（A・G）の中央を画面の左右端から 20 の位置とし、間を均等（80 間隔）に並べる（x = 20, 100, 180, 260, 340）
      - 両端のレーンは画面外にはみ出すため、レーンの中央には揃えない。各文字は対応するレーンの押下範囲に収まる
    - キーボードがありそうな環境（PC）でのみ表示する。表示条件は Title の説明文と同じ（`docs/spec/title.md`「説明文の表示条件」）
- 判定の結果
  - 判定の結果を、判定したノーツのレーンの判定バーの少し上に表示する（「判定」を参照）
  - 表示位置: x はレーンの中央（判定バーの位置。x = 36, 108, 180, 252, 324）、y = 496（判定バーの 16 上）
  - 文字は `GREAT` / `GOOD` / `BAD` / `MISS`、Orbitron の太字、サイズ 12、横中央揃え
  - 色は Great がネオン調の桃色（`#ff5fd2`）、Good がネオン調の青（`#4fc3ff`）、Bad が白（`#fff`）、Miss が灰色（`#888`）。Great・Good のみ発光させる

## レーンの形
- 配置

  | 項目 | y | レーン全体の幅 |
  |---|---|---|
  | 上端 | 128（画面の上 2 割） | 90（画面幅の 25%） |
  | 判定バー | 512（画面の下 2 割） | 360（画面幅と一致） |
  | 下端 | 640（画面の最下部） | 450（左右に 45 ずつはみ出し、画面外は表示されない） |

- 各レーンは判定バーの位置で幅 72（画面幅の 5 等分）となり、横の中央（x = 180）に向かって奥ほど狭くなる
- 上端から 96（`SCENE_HEIGHT * 0.15`）の長さで、上に向かってフェードアウトさせる（背景・境界線とも）

### 奥行きの表現
- 透視投影で奥行きを表現する。判定バーの位置を基準に、奥ほど縮小率を小さくする
  - 縮小率 `s = 1 / (1 + 3d)`（d は奥行き。判定バーで 0、レーン上端で 1、判定バーより手前は負の値）
  - 上端（d = 1）で縮小率 0.25、下端で 1.25（d = -1/15）となる
- 消失点は (180, 0)（Scene の上端の中央）
- 判断の経緯は `docs/decisions/002-lane-perspective.md` を参照

## 小節線
- 小節の頭の時刻に、小節線が判定バーの位置に来るように流す
  - 1 小節目の頭を曲の先頭（再生位置 0ms）とし、n 小節目の頭は `(n - 1) × 1 小節の時間`
  - 1 小節の時間は、Title から渡される曲のテンポと拍子から `60000 / BPM × 1 小節の拍数`（ms）で求める（仮の音源では 2000ms）
  - 曲の先頭より前（leadIn の間）の小節線は表示しない
  - 曲の終了後も、小節線は同じ間隔で流れ続ける
- 位置は再生位置（「再生位置」を参照）から、表示のフレームごとに求める
- 流れ方
  - レーン上端から判定バーまで 4000ms で達する
  - 奥行き（「奥行きの表現」の d）は時刻に対して線形に変化させる: `d = (小節の頭の時刻 - 再生位置) / 4000`
    - 透視投影により、奥ほど幅が狭く、ゆっくり・間隔が詰まって見える
  - レーン上端（d = 1）に現れ、レーンと同じ範囲でフェードアウトした状態から見えるようになる
  - 判定バーを通過した後は、画面の下端（d = -1/15）まで流れて消える
  - 表示範囲（d が -1/15〜1）の外にある小節線は描画しない

## ノーツ
- 譜面
  - Title から渡される曲（Track）に含まれる譜面（`docs/spec/title.md`「曲の読み込み」）に従ってノーツを流す
  - 各ノーツは、判定バーに達する時刻 `hitTime`（ms、曲の先頭を 0 とする）と、レーン番号 `lane`（左から 0〜4）を持つ
  - 譜面のノーツが `hitTime` の昇順に並んでいることは前提としない
  - `hitTime` が負のノーツや、leadIn の間に表示範囲に入るノーツも、譜面のとおりに流す
  - 譜面は固定のデータのため、実行時の検証は行わない（レーン番号が範囲外のノーツなどは考慮しない）
- 形
  - レーン面上の長方形を、奥行きの表現（「奥行きの表現」）に合わせて投影した台形として描く
  - 幅: 判定バーの位置で 60（レーン幅 72 から左右に 6 ずつ余白をとる）。奥ほど狭くなる
  - 厚み（奥行き方向の長さ）: 判定バーの位置での高さ 12 に相当する奥行き 0.008（時間にして 32ms）で一定とする。奥ほど薄く見える
- 流れ方
  - 小節線（「小節線」）と同じく、レーン上端から判定バーまで 4000ms で達し、奥行きは時刻に対して線形に変化させる: `d = (hitTime - 再生位置) / 4000`
  - d はノーツの厚みの中央の奥行きとする。`hitTime` の時点で、ノーツの中央が判定バーに重なる
  - 位置は再生位置（「再生位置」を参照）から、表示のフレームごとに求める
  - レーン上端に現れ、レーンと同じ範囲でフェードアウトした状態から見えるようになる
  - 押下で判定された（Great / Good / Bad の）ノーツは、判定の時点で表示から消す（「判定」を参照）
  - 判定されずに判定バーを通過したノーツ（Miss となるノーツを含む）は、そのまま画面の下端まで流れて消える
  - 一部でも表示範囲（d が -1/15〜1）にかかるノーツを描画し、それ以外は描画しない

## 入力
- キーボードのキー、または入力ボタンの押下で、レーンごとに入力する
- 押下の開始（キー・ボタンを押した時点）で、そのレーンの判定を行う（「判定」を参照）。離したときには何もしない
- キーまたはボタンを押している間は、そのレーンの入力ボタンを押下中の表示にする（「表示要素」の「入力ボタン」を参照）

### キーボード
- レーン 0〜4 に、それぞれ `A` / `S` / `D` / `F` / `G` キーを割り当てる
  - キーは物理的なキーの位置（`KeyboardEvent.code` の `KeyA`〜`KeyG`）で判別し、キーボード配列・IME・Caps Lock の状態によらない
  - 修飾キー（Ctrl など）との同時押しは区別しない
- Play の表示中は、どこにフォーカスがあっても有効
- 複数のキーの同時押しに対応する
- キーの押しっぱなしによるリピートは無視する
- ウィンドウのフォーカスが外れたときは、押下中のキーをすべて離したものとして扱う（離したことを検知できないため）

### 入力ボタン（タッチ・マウス）
- 押下範囲: 判定バーより下の領域（x = 0〜360、y = 512〜640、両端を含む）を横に 5 等分した長方形（各幅 72）とし、左からレーン 0〜4 に対応させる
  - 見た目（判定バーより下のレーンの台形）とは別に定める。判定バーの位置では各レーンの幅と一致し、下に行くほど少しずれる
  - 両端のレーンが画面外にはみ出しても、押下範囲はレーンごとに均等にする
  - レーンの境界の x（72, 144, 216, 288）は右のレーンに含める
  - 判定バーより上の領域は押下範囲に含めない（指でノーツが隠れるのを避けるため）
- タッチ・マウスのどちらでも押せる。マウスは主ボタンのみ受け付ける
- 複数のボタンの同時押し（マルチタッチ）に対応する
- 押下中に指（ポインタ）を別のレーンへ動かしても、押下中のレーンは押下を始めたレーンのままとする（スライドによる入力はしない）
- 押下範囲の上に重なるノーツ・判定バーなどの表示要素は、押下を妨げない

## 判定
- ノーツに対する押下のタイミングを Great / Good / Bad / Miss の 4 種類で評価する
- 判定の範囲: 押下の時刻とノーツの `hitTime` のずれ（絶対値）で決める

  | 判定 | ずれ |
  |---|---|
  | Great | 75ms 以内 |
  | Good | 75ms を超え 150ms 以内 |
  | Bad | 150ms を超え 225ms 以内 |

  - 早押し・遅押しで範囲を変えない（対称とする）
- 押下の時刻は、押下の時点の再生位置（「再生位置」と同じく音声のクロックを基準とする）とする
  - 表示のフレームの更新を待たず、押下のイベントの時点で求める
- 押下の判定
  - 押下したレーンのノーツのうち、判定済みでなく、ずれが 225ms 以内のノーツを判定の対象とする
    - 対象が複数ある場合は、`hitTime` が最も早いノーツを対象とする（手前のノーツを飛ばして後のノーツを判定しないため）
  - 対象のノーツがない押下（空押し）は何もしない
  - 判定したノーツは以降の判定の対象から外し、表示から消す
- Miss
  - 判定済みでなく、再生位置が `hitTime` から 225ms を超えて過ぎたノーツを Miss とする（表示のフレームごとに検出する）
  - Miss のノーツは表示から消さず、画面の下端まで流す（見逃したことが分かるようにするため）
- 判定の結果の表示
  - 判定（Miss を含む）が行われると、そのレーンの判定の結果を 500ms の間表示する（「表示要素」の「判定の結果」を参照）
    - 経過時間は再生位置で数える
  - 同じレーンで続けて判定が行われた場合は、新しい結果に置き換え、表示時間も新しい結果から数え直す
  - 判定時のエフェクトは判定の結果の表示のみで、表示・非表示の切り替えにアニメーションは付けない
- ずれの補正（出力のレイテンシ・入力の遅延）は行わない

## 曲の再生
- Title の開始の操作で予約された曲（`docs/spec/title.md`「開始の操作」）を、Play の表示中に再生する
  - 曲は開始の操作から leadIn（1 小節の時間。仮の音源では 2000ms）後に再生が始まる。Scene の切り替えのフェード（400ms）の後に間を置くためのもの
- 曲の終了に対する処理は行わない（曲の終了後も小節線は流れ続ける）
  - TODO: 曲終了後の挙動は検討中
- Play が取り除かれるときに、曲の再生を停止する（現状は Play からの遷移はない）
- 一時停止・シーク・音量調整などの操作はない

### 再生位置
- 曲の先頭を 0 とした再生位置（audioTime）を ms 単位で、表示のフレームごとに更新する
  - 時刻は音声のクロック（`AudioContext.currentTime`）を基準とし、開始からの経過時間を別の時計で積算しない
  - 曲の再生が始まるまで（leadIn の間）は負の値になる
  - 曲の終了後も、曲の長さを超えて増え続ける
  - 出力のレイテンシ（`AudioContext.currentTime` は実際にスピーカーから音が出る時刻より `outputLatency` 分先行する）は補正しない

### 開発時の表示
- 開発時（`import.meta.env.DEV`）のみ、再生位置の確認のため、Scene の左上に `audioTime: <再生位置(ms、整数に丸める)> ms` を白字の等幅フォントで表示する
- 本番のビルドでは表示されない
