# 002: レーンの奥行き表現は投影の計算を純粋関数で行い、SVG に直接描く

- 日付: 2026-10-21
- 関連タスク: `tasks/20261021-play-bg/`

## 背景
ゲーム画面（Play）のレーンを奥行きのある表現（手前が広く、奥が狭い台形）で表示する。
後続のタスクでノーツを落下させるとき、透視投影らしく見せるには、奥ほど小さく、ゆっくり動くようにノーツを描く必要がある。
レーンとノーツを奥行きのある形にどう変換して描くかを決める必要があった。

なお、SVG の `transform` 属性は 2D のアフィン変換のみで、平行な線を平行なまま保つため、長方形を台形に変換できない。

## 決定
- 奥行きのない座標（レーン上の横位置と奥行き）を、論理座標の位置と縮小率に変換する投影の関数を `src/lib/` に純粋関数として置く
- レーンもノーツも、この関数で変換した座標を使い、Scene の SVG（論理座標）に直接描く
  - 例: ノーツは 4 隅を変換した `<polygon>` として描く
- 3D 変換は使わない

## 理由
- Scene の構成（Scene が Stage いっぱいの svg を 1 枚持ち、論理座標で描く）を変えずに済む
- 投影の計算は数行の式で済み、`docs/architecture.md`「ゲームロジックの分離」の方針どおり、Vitest でテストできる
- 見た目が画面サイズに依存しない（すべて論理座標で完結する）
- レーンとノーツが同じ関数を使うため、両者の位置が必ず一致する

## 検討した他の案
- 奥行きのない SVG を描き、CSS の 3D 変換（`perspective` + `rotateX`）で傾ける
  - 良い点: ノーツを長方形として直線的に動かすだけで、奥ほど小さく遅く見える表現をブラウザが行う
  - 3D 変換は SVG 内の要素には主要ブラウザで十分に効かないため、HTML 要素や別の `<svg>` 要素にかける必要があり、Scene が複数のレイヤの重ね合わせになる（判定の文字などは傾けない層に分ける）
  - `perspective` は CSS の長さで指定するため、Stage のサイズに合わせるには container query の単位などで論理座標との対応をとる必要がある
  - 要件の配置（レーン上端の位置と幅、判定バーで画面幅と一致）に合わせるには、`perspective`・角度・`transform-origin` を逆算する必要がある
  - 3D 変換した層はラスタライズされて変形されるため、奥の細い線がにじむことがある。タップの当たり判定の確認も必要になる
