# Proposal

Svelte で作るリズムゲームの習作。

## 目的
- Svelte で簡単なゲームであればシンプルなコードで作れることを示す
- ブラウザゲームの基本的な手法について学ぶ（requestAnimationFrame でのフレーム制御と描画）

## 概要
- 収録曲は 1 曲のみ（曲は後で自作する予定）
- 画面は以下の 2 つ
  - 開始画面
  - ゲーム画面

## スコープ
### やること
- 開始画面からゲーム画面への遷移
- ノーツの落下と判定
- スコア表示
- 1 曲分の再生
- リザルトの表示（ゲーム画面上のポップアップを想定）

### やらないこと
- 曲の選択
- 譜面エディタ
- ランキングやオンライン機能
- 難易度の切り替え
- 設定画面

## 技術的な制約
- Svelte 5 で実装する
- SvelteKit は個人的嗜好により、必須でない限り使わない
- ブラウザで動くゲームであり、バックエンドは不要
- ゲーム画面は SVG で構成する
  - Canvas での描画より SVG（または DOM）の方が Svelte との相性が良いため
- 音声データは、単純化のため譜面データと音声を同時に開始すれば良いように作成する（プログラム側での調整を不要にする）
  - technical note: 音声側の `audio.currentTime` などに譜面の進行を合わせる形にすればズレは少なくなる

### 画面サイズ
- 縦画面を前提とし、ゲーム領域の縦横比は 9:16 で固定する
- スマホではブラウザの表示領域いっぱい、PC（および横向きのスマホ）では縦長の領域を中央に配置する
  - 縦長すぎる端末では上下に余白が出ることを許容する
  - 検討: 幅固定・高さ可変（端末の縦横比に合わせて画面を使い切る）案もあったが、実装の単純さと端末間で見え方を揃えることを優先して 9:16 固定とした
- ゲーム画面は SVG の論理座標（viewBox）で描画し、実際の画面サイズに依存しないようにする
- Fullscreen API は使わない（iOS Safari が非対応のため）
- タッチ操作時のスクロール・拡大・テキスト選択を抑止する
- viewBox の具体的なサイズなどの数値は spec で決める

## ゲーム仕様（暫定）
プロポーザル段階での仕様であり、将来的には `docs/spec/` 以下のドキュメントを正とする。

- オーソドックスな、ノーツが上から降ってきて判定バーに触れるタイミングでボタンを押すタイプのゲーム
- レーン数: 5
- 判定: Great / Good / Bad / Miss の 4 種類。ボタンを押したタイミングがどれだけ一致しているかにより判定が変わる
- 入力: キーボードまたはタッチ。どちらか一方だけで操作が完結するように作る
  - 例: 開始ボタンの下に「SPC で開始」のような注意書きを表示し、タップ / キーボードのどちらでも開始できるようにする

## マイルストーン
以降のタスクの候補。

1. 画面の骨組み（開始画面からゲーム画面への遷移、キーボードとタップの両方で開始）
2. SVG のレーンとノーツの落下（rAF、仮の譜面を読み込む）
3. 入力と判定（キーボードとタッチ、Great / Good / Bad / Miss）
4. スコアとリザルトのポップアップ
5. 音声との同期（時刻の基準を音声の再生位置にする）と仮の音源
6. 自作曲と譜面に差し替える
