# docs

## 目的・定義
- `docs/` 内のドキュメントは以下の目的で作成する
  1. 実装者のシステムの理解を助ける
  2. コーディング規約など、実装に一貫性を持たせるための基準を作る
     - これも最終的にはコードの分かりやすさ = システムの理解しやすさを保つために作成する
- `docs/spec/` は現行の実装・仕様を説明するものであり、将来的な仕様は記載しない

## 構成

```
docs/
  + proposal.md      # プロジェクトの目的・スコープ・全体要件（初期の計画。以降の docs と矛盾してもよく、矛盾する場合は他の docs を優先する）
  + architecture.md  # プロジェクトの基本的な設計
  + glossary.md      # 用語集（プロジェクト固有の概念、ソースコードに現れる用語、またはそれらが表す概念のみ）
  + coding-guidelines.md  # コーディング規約（lint で表現できないもの）
  + spec/                 # 仕様
    + <feature_name>.md   # 機能ごとの外部仕様
  + decisions/              # ADR: アーキテクチャについての検討内容を記録したもの
    + <num>-<short-name>.md # 例: 001-scene-transition.md など、連番とタイトルを短い英語で表す。トレードオフを伴う意思決定について判断理由を含めて記録する。
```
